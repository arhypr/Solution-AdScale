отказоустойчивость (RPO/RTO, резервное копирование, соответствие 12-факторным приложениям).

## Ключевые решения

- **Database per Service** — каждый микросервис владеет своей БД, чтобы избежать связности и обеспечить независимое
  масштабирование.
- **Выбор СУБД**:
    - *Bidding Service* и *Campaign Service* — PostgreSQL (OLTP) с Redis для кэширования.
    - *Statistics Service* — ClickHouse (колоночная, для высоконагруженной записи событий).
    - *Analytics Service* — PostgreSQL read replica + ClickHouse для аналитики.
    - *Financial Service* — PostgreSQL с повышенной надёжностью (репликация).
- **Масштабирование**: Master-Slave репликация для PostgreSQL, шардирование по `advertiser_id` для кампаний и финансов,
  read replicas для аналитики, CQRS разделяет команды (запись) и запросы (чтение через read replicas).
- **Кэширование**: Redis Cluster для кэширования кампаний, ставок, таргетинговых данных. TTL – 5 минут, инвалидация по
  событиям обновления через Kafka. Прогрев кэша при старте и перезагрузке по расписанию.
- **Потоковая обработка**: Kafka с топиками `bid-wins`, `impressions`, `clicks`, `budget-updates`. Схема – Avro для
  строгой типизации и обратной совместимости. Группы потребителей для Financial Service, Statistics, Analytics.
- **Отказоустойчивость**: RPO = 15 минут (для финансов) и 1 час (для остальных); RTO = 1 час. Резервное копирование (
  pg_dump + WAL-архивация), репликация для HA. Соответствие 12-факторам (храним конфигурацию в переменных окружения,
  логируем в stdout, используем внешние сервисы для бэкендов).
