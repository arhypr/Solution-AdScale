## Краткое описание

В рамках данного задания спроектирован критический компонент — **сервис ставок (Bidding Service)**, выделенный из
монолита для обеспечения высокой производительности и соблюдения SLA при интеграции с новой DSP-площадкой. Определены
границы сервиса, его API, модель данных и зависимости. Разработаны схемы взаимодействия как с внешними DSP-партнёрами (
по OpenRTB), так и внутри системы (gRPC, Kafka). Спроектирован API Gateway для маршрутизации, аутентификации, rate
limiting и обеспечения надёжности через паттерны Circuit Breaker и retries.

## Ключевые решения

- **Bidding Service** выделен как отдельный микросервис на C++/Go с использованием Redis для кэширования кампаний и
  ставок.
- **Внешний протокол** — OpenRTB через HTTPS (синхронный запрос-ответ).
- **Внутренняя коммуникация** — gRPC для low-latency вызовов между Ad Server и Bidding Service.
- **Событийная шина** — Apache Kafka для асинхронной доставки событий (показы, клики, метрики).
- **API Gateway** (Kong/Envoy) обеспечивает единую точку входа, аутентификацию, rate limiting и Circuit Breaker для
  защиты сервиса ставок.
- **Надёжность** реализована через паттерны: Retry с экспоненциальной задержкой, Circuit Breaker, идемпотентность
  финансовых операций, кэшированные дефолтные ставки при сбоях.
