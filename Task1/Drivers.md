# Архитектурные драйверы

## 1. Функциональные требования (после интеграции с DSP)
| ID | Требование |
|----|------------|
| FR1 | Приём bid requests от DSP-партнёра по OpenRTB и формирование bid responses |
| FR2 | Проведение аукциона в реальном времени с применением бизнес-правил (таргетинг, бюджет, ставки) |
| FR3 | Формирование HTML/JS-разметки баннера для показа |
| FR4 | Сбор статистики (показы, клики, конверсии) с гарантированной доставкой |
| FR5 | Управление рекламными кампаниями, бюджетами, ставками через личный кабинет |
| FR6 | Финансовые операции: списание средств, выставление счетов, ведение балансов |
| FR7 | Предоставление аналитической отчётности рекламодателям |

## 2. Атрибуты качества (с приоритетами)

| Приоритет | Атрибут | Требуемое значение | Обоснование |
|-----------|---------|---------------------|-------------|
| **1** | **Производительность (Latency)** | P95 ≤ 100 мс (через 3 мес); P95 ≤ 80 мс (через год) | Критично для RTB-аукционов; штрафы за превышение |
| **2** | **Масштабируемость (Scalability)** | Поддержка 18 000 RPS через 3 мес, 50 000 RPS через год | Рост пользователей и интеграция с DSP |
| **3** | **Доступность (Availability)** | SLA 99.9% (через год) | Бизнес-требование; недопустимость простоев |
| **4** | **Надёжность (Reliability)** | Отказоустойчивость, отсутствие SPOF, самовосстановление | Критично для финансовых операций и аукционов |
| **5** | **Безопасность (Security)** | Защита данных, шифрование трафика, аутентификация/авторизация | Обработка платежей и персональных данных |
| **6** | **Наблюдаемость (Observability)** | Метрики, логи, трассировка в реальном времени | Быстрое выявление и устранение проблем |
| **7** | **Удобство разработки (Maintainability)** | Модульность, документированность, CI/CD | Ускорение вывода изменений и снижение рисков |

## 3. Технические ограничения
- **Бюджет:** ограничен, нельзя закупать дорогостоящие проприетарные решения.
- **Срок:** 3 месяца на промежуточное решение, год на финальное.
- **Команда:** 35 человек, нет выделенных SRE, техписателя, бизнес-аналитика.
- **Нельзя переписать всё с нуля** — только постепенная миграция.
- **Непрерывность бизнеса:** система должна оставаться работоспособной на всех этапах.
- **Технологический стек:** преимущественно Open Source (PostgreSQL, Kafka, Redis, Kubernetes).

## 4. Бизнес-ограничения
- Удержание текущих клиентов и их SLA (≤100 мс).
- Подключение нового DSP-партнёра с жёстким SLA (≤80 мс).
- Финансовые штрафы за недостижение SLA.
- Конкурентная среда: потеря аукциона означает потерю выручки.
